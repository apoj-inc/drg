# GitLab MCP

This service exposes the GitLab Model Context Protocol (MCP) server through
the GitLab HTTPS endpoint.

## Endpoint

```text
https://git.example.test/api/v4/mcp
```

The `/mcp` path is not the MCP endpoint. Without authentication it returns the
GitLab sign-in page. The `/api/v4/mcp` endpoint requires GitLab authentication.

## Traefik routing

The route is defined in `services/gitlab/traefik.yml` and is generated by the
managed Traefik configuration:

- Host: `git.example.test`
- HTTPS entrypoint: `websecure`
- Backend: GitLab HTTP port `80`
- Middleware: `secure-headers`, `rate-limit`
- Git SSH: TCP port `2222`, routed separately

Traefik terminates TLS and forwards requests to GitLab. GitLab trusts the
Traefik proxy network configured in `services/gitlab/config.yaml`.

## Codex CLI setup

Add the GitLab MCP server to the local Codex configuration:

```powershell
codex mcp add gitlab --url https://git.example.test/api/v4/mcp
codex mcp login gitlab
codex mcp list
```

`codex mcp login gitlab` opens the OAuth authorization flow. Complete the
login in the browser and approve the requested GitLab access. OAuth credentials
are stored by Codex; do not paste access tokens into this repository or into
chat messages.

After authentication, restart Codex or open a new session. In the Codex TUI,
use `/mcp` to inspect the active server and its tools.

## Desktop or IDE setup

Add a new MCP server using the `Streamable HTTP` transport and this URL:

```text
https://git.example.test/api/v4/mcp
```

Authenticate the server when prompted, then restart the MCP integration if the
server does not appear immediately.

## Manual config.toml entry

The equivalent local Codex configuration is:

```toml
[mcp_servers.gitlab]
url = "https://git.example.test/api/v4/mcp"
auth = "oauth"
default_tools_approval_mode = "writes"
```

Run `codex mcp login gitlab` after adding the entry.

## Windows: `codex` is not recognized

If PowerShell reports that `codex` is not recognized, run the installed
executable by its full path:

```powershell
& "$HOME\.codex\.sandbox-bin\codex.exe" mcp login gitlab
```

To make `codex` available for the current PowerShell session, add its
directory to `PATH`:

```powershell
$env:Path += ";$HOME\.codex\.sandbox-bin"
codex mcp login gitlab
```

Open a new terminal after making a permanent user `PATH` change.

## Verification

Check that the server is configured:

```powershell
codex mcp list
```

An unauthenticated protocol request returning `401 Unauthorized` is expected
and confirms that the endpoint is reachable and protected. A successful OAuth
login should allow Codex to initialize the server and list its tools.

If authentication fails, verify that:

1. The GitLab MCP server is enabled for the self-managed instance.
2. The GitLab user is allowed to access the target projects and groups.
3. The exact endpoint is `/api/v4/mcp`.
4. The Traefik route is deployed and the GitLab service is healthy.

## Safety

GitLab MCP tools can read repository, issue, merge request, CI, and work item
data. Some tools can create or modify GitLab objects. Keep write approvals
enabled and review tool arguments before accepting changes. Use only trusted
GitLab projects and treat repository content as untrusted input.
